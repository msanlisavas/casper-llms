# casper-client 5.x: sending transactions on Casper 2.x

Verified against casper-client-rs v5.0.1 on 2026-09-10.

casper-client 5.0.1 is the latest casper-client-rs release, and it builds Casper 2.x `Transaction`s with `put-transaction` or with the offline `make-transaction` → `sign-transaction` → `send-transaction` flow ([release v5.0.1](https://github.com/casper-ecosystem/casper-client-rs/releases/tag/v5.0.1), [put.rs#L53-L58](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/put.rs#L53-L58), [make.rs#L18-L22](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/make.rs#L18-L22)). The 1.x-era `put-deploy`, `make-deploy`, `sign-deploy` and `send-deploy` commands still run but print a deprecation warning ([deploy/put.rs#L11-L42](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/deploy/put.rs#L11-L42), [deploy/make.rs#L11-L45](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/deploy/make.rs#L11-L45), [deploy/sign.rs#L11-L45](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/deploy/sign.rs#L11-L45), [deploy/send.rs#L12-L42](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/deploy/send.rs#L12-L42)). Every `put-transaction`/`make-transaction` subcommand requires `--chain-name` and `--gas-price-tolerance`, and on Mainnet and Testnet you must use the default `classic` pricing mode, which also needs `--payment-amount` and `--standard-payment`, where `true` selects standard payment and `false` custom payment ([creation_common.rs#L201-L214](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L201-L214), [creation_common.rs#L399-L444](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L399-L444), [creation_common.rs#L485-L500](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L485-L500), [creation_common.rs#L742-L778](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L742-L778), [parse.rs#L923-L960](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L923-L960), [mainnet chainspec#L129-L139](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L129-L139), [testnet chainspec#L135-L139](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L135-L139), [meta_transaction.rs#L117-L133](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction.rs#L117-L133), [meta_transaction_v1.rs#L577-L593](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L577-L593)). `--transfer-amount` and `--transaction-amount` take integer motes, and one CSPR is 1,000,000,000 motes; `--payment-amount` is a gas limit, which costs the same number of motes because both networks fix the gas price at 1 ([docs.casper.network: Motes](https://docs.casper.network/concepts/glossary/M), [M.md#L19](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/glossary/M.md#L19), [creation_common.rs#L1527-L1558](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L1527-L1558), [creation_common.rs#L2478-L2479](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2478-L2479), [pricing_mode.rs#L142-L171](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L142-L171), [mainnet chainspec#L509-L510](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L509-L510), [testnet chainspec#L511-L512](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L511-L512)).

## Install

- The v5.0.1 release note says it updated casper-types to 7.0.0 "to let the casper client be compatible with the v2.2.0 protocol of the casper node" ([release v5.0.1](https://github.com/casper-ecosystem/casper-client-rs/releases/tag/v5.0.1)).
- The release has no uploaded binaries; its only assets are GitHub's auto-generated source-code archives ([release v5.0.1](https://github.com/casper-ecosystem/casper-client-rs/releases/tag/v5.0.1)).
- The crate and its binary are both named `casper-client`, and the crate version is 5.0.1 ([Cargo.toml#L2-L3](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/Cargo.toml#L2-L3), [Cargo.toml#L20-L22](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/Cargo.toml#L20-L22)).
- The repository pins Rust 1.85.0, while the docs' prerequisites page still says to install the nightly toolchain before compiling the client ([rust-toolchain.toml#L2](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/rust-toolchain.toml#L2), [docs.casper.network: Development Prerequisites](https://docs.casper.network/developers/prerequisites), [prerequisites.md#L157-L161](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/prerequisites.md#L157-L161)).
- On Linux, the docs list `pkg-config`, `openssl` and `libssl-dev` as packages required for Casper tools, and the client's lock file includes `native-tls` and `openssl-sys` ([docs.casper.network: Development Prerequisites](https://docs.casper.network/developers/prerequisites), [prerequisites.md#L32-L38](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/prerequisites.md#L32-L38), [Cargo.lock#L1296-L1305](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/Cargo.lock#L1296-L1305), [Cargo.lock#L1448-L1457](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/Cargo.lock#L1448-L1457)).
- The casper-client 5.0.1 binary does not compile on native Windows. It requires the `std-fs-io` feature, which turns on the same feature in casper-types 7.0.0, and that compiles `file_utils.rs` (a `std::os::unix::fs::OpenOptionsExt` import and a `.mode(0o600)` call) and a `libc::sysconf`/`_SC_PAGESIZE` import in `lib.rs`, none of them gated to Unix ([Cargo.toml#L24-L28](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/Cargo.toml#L24-L28), [Cargo.toml#L35](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/Cargo.toml#L35), [types/Cargo.toml#L3](https://github.com/casper-network/casper-node/blob/057cf21c9c534121f06aa03d370df8f42352d9c3/types/Cargo.toml#L3), [lib.rs#L48-L49](https://github.com/casper-network/casper-node/blob/057cf21c9c534121f06aa03d370df8f42352d9c3/types/src/lib.rs#L48-L49), [lib.rs#L78-L79](https://github.com/casper-network/casper-node/blob/057cf21c9c534121f06aa03d370df8f42352d9c3/types/src/lib.rs#L78-L79), [file_utils.rs#L3-L8](https://github.com/casper-network/casper-node/blob/057cf21c9c534121f06aa03d370df8f42352d9c3/types/src/file_utils.rs#L3-L8), [file_utils.rs#L59-L78](https://github.com/casper-network/casper-node/blob/057cf21c9c534121f06aa03d370df8f42352d9c3/types/src/file_utils.rs#L59-L78)). On Windows, build it in a Linux environment such as WSL: the client's `ci-casper-client-rs` workflow builds and tests it only on `ubuntu-22.04` ([ci-casper-client-rs.yml#L16-L21](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/.github/workflows/ci-casper-client-rs.yml#L16-L21), [ci-casper-client-rs.yml#L68-L83](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/.github/workflows/ci-casper-client-rs.yml#L68-L83)), its tag-triggered Debian-package workflow builds it on `ubuntu-22.04` and `ubuntu-24.04` ([publish-casper-client-deb.yml#L14-L22](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/.github/workflows/publish-casper-client-deb.yml#L14-L22), [publish-casper-client-deb.yml#L58-L62](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/.github/workflows/publish-casper-client-deb.yml#L58-L62)), and the docs recommend Linux Ubuntu 20.04 or macOS and say developing on Windows is not advised ([docs.casper.network: Development Prerequisites](https://docs.casper.network/developers/prerequisites), [prerequisites.md#L7](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/prerequisites.md#L7)).
- A build from a v5.0.1 checkout takes casper-types from the casper-node `dev` branch through `[patch.crates-io]`, and the checked-in `Cargo.lock` pins that dependency to commit 057cf21c ([Cargo.toml#L61-L62](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/Cargo.toml#L61-L62), [Cargo.lock#L236-L238](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/Cargo.lock#L236-L238)).
- `casper-client --version` prints `Casper client` and the crate version, with a short git hash appended when the build could read one ([main.rs#L63-L77](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/main.rs#L63-L77), [main.rs#L119-L121](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/main.rs#L119-L121), [build.rs#L6-L17](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/build.rs#L6-L17)).

```bash
cargo install casper-client --version 5.0.1 --locked
casper-client --version
```

## Node address, chain name and units

- `--node-address` (short `-n`) defaults to `http://localhost:7777` ([common.rs#L45-L60](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/common.rs#L45-L60)).
- The client appends `/rpc` to the address unless it already ends in `rpc`, so pass `http://<NODE-ADDRESS>:7777` ([call.rs#L11](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/json_rpc/call.rs#L11), [call.rs#L35-L39](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/json_rpc/call.rs#L35-L39)).
- The docs give 7777 as the default port of the sidecar's JSON-RPC server on Mainnet and Testnet ([docs.casper.network: Sending Transactions](https://docs.casper.network/developers/cli/sending-transactions), [sending-transactions.md#L55](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/sending-transactions.md#L55)).
- The chain name is `casper` on Mainnet and `casper-test` on Testnet ([mainnet chainspec#L20](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L20), [testnet chainspec#L20](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L20), [docs.casper.network: Sending Transactions](https://docs.casper.network/developers/cli/sending-transactions), [sending-transactions.md#L56](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/sending-transactions.md#L56)).
- Transfer, delegation and bid amounts are integers in motes: `--transaction-amount` is described as "the amount of CSPR motes for the transaction" and is parsed as a decimal U512, so `2.5` is rejected, and `--transfer-amount` goes through the same parser ([creation_common.rs#L1527-L1558](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L1527-L1558), [creation_common.rs#L2478-L2479](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2478-L2479)).
- `--payment-amount` is parsed as a u64 and `--gas-price-tolerance` as a u8, so the client accepts a tolerance of at most 255, but a v2.2.2 node on Mainnet or Testnet accepts only 1 ([parse.rs#L942-L954](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L942-L954), [meta_transaction_v1.rs#L100-L128](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L100-L128), [mainnet chainspec#L509-L510](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L509-L510), [testnet chainspec#L511-L512](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L511-L512)).
- `--payment-amount` is a gas limit, not a mote amount: `classic` turns it into a `PaymentLimited` pricing mode, whose gas limit is the payment amount and whose cost in motes is the payment amount times the gas price. Both networks fix `min_gas_price` and `max_gas_price` at 1, so today a payment amount costs the same number of motes ([parse.rs#L923-L965](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L923-L965), [pricing_mode.rs#L142-L171](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L142-L171), [mainnet chainspec#L509-L510](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L509-L510), [testnet chainspec#L511-L512](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L511-L512)).

## Keys: `keygen`

```bash
casper-client keygen <PATH-TO-KEYS-DIR>                         # Ed25519 (default)
casper-client keygen --algorithm secp256k1 <PATH-TO-KEYS-DIR>
```

- The output directory is a positional argument; without it, keygen writes to the current directory ([src/keygen.rs#L33-L52](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/keygen.rs#L33-L52)).
- keygen writes `secret_key.pem`, `public_key.pem` and `public_key_hex`; the hex file carries an algorithm tag prefix, `01` for Ed25519 and `02` for secp256k1 ([lib/keygen.rs#L9-L29](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/keygen.rs#L9-L29)).
- `--algorithm` (short `-a`) takes exactly `Ed25519` or `secp256k1` through a clap possible-values parser, so `ed25519` and `SECP256K1` are rejected; the default is `Ed25519` ([src/keygen.rs#L59-L77](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/keygen.rs#L59-L77), [lib/keygen.rs#L19-L22](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/keygen.rs#L19-L22)).
- Without `-f`/`--force`, keygen refuses to run if any of the three files already exists ([common.rs#L121-L138](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/common.rs#L121-L138), [lib/keygen.rs#L48-L54](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/keygen.rs#L48-L54)).
- `secret_key.pem` is written through casper-types' `write_private_file`, which opens it with mode `0o600` so only the owner can read or write it ([lib/keygen.rs#L75-L81](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/keygen.rs#L75-L81), [asymmetric_key.rs#L243-L244](https://github.com/casper-network/casper-node/blob/057cf21c9c534121f06aa03d370df8f42352d9c3/types/src/crypto/asymmetric_key.rs#L243-L244), [file_utils.rs#L59-L78](https://github.com/casper-network/casper-node/blob/057cf21c9c534121f06aa03d370df8f42352d9c3/types/src/file_utils.rs#L59-L78)).
- `secret_key.pem` holds the secret key that `sign-transaction` and `--secret-key` use to sign, so keep it private and share only the public key ([lib/keygen.rs#L27-L29](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/keygen.rs#L27-L29), [sign.rs#L13-L16](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/sign.rs#L13-L16)).

## The transaction command family

| Command | Alias | What it does | Source |
|---|---|---|---|
| `put-transaction <SUBCOMMAND>` | `put-txn` | Creates a transaction and sends it to the node | [put.rs#L53-L58](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/put.rs#L53-L58) |
| `make-transaction <SUBCOMMAND>` | none | Creates a transaction and writes it to `--output` or stdout | [make.rs#L18-L22](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/make.rs#L18-L22) |
| `sign-transaction` | none | Reads a saved transaction, signs it, writes it out | [sign.rs#L13-L16](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/sign.rs#L13-L16) |
| `send-transaction` | `send-txn` | Sends a saved transaction file to the node | [send.rs#L12-L18](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/send.rs#L12-L18) |
| `get-transaction <HASH>` | `get-txn` | Retrieves a transaction from the network | [get.rs#L25](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/get.rs#L25), [get.rs#L58-L59](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/get.rs#L58-L59) |
| `list-transactions` | none | Lists the transaction hashes in a block | [list.rs#L57-L58](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/list.rs#L57-L58) |

- `put-transaction` must sign, so give it `--secret-key`. With only `--initiator-address` it fails with "No secret key provided and unsigned deploys are not allowed"; with neither flag, clap reports the missing `--secret-key`/`--initiator-address` group. `make-transaction` accepts `--initiator-address` alone and writes an unsigned transaction ([lib/cli/transaction.rs#L130-L159](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L130-L159), [lib/cli/transaction.rs#L445-L469](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L445-L469), [creation_common.rs#L742-L750](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L742-L750)).
- Before sending, every `put-transaction` fetches the latest block from `--node-address` with `chain_get_block`, whatever the subcommand; if that request fails and `--min-bid-override` is not set, nothing is sent ([lib/cli/transaction.rs#L149-L172](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L149-L172), [lib/cli/transaction.rs#L472-L485](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L472-L485), [get_block.rs#L7](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/rpcs/v1_4_5/get_block.rs#L7)).
- `sign-transaction` takes `--secret-key`/`-k` (required), the input transaction file through `--wasm-path`/`-w` (required, even though its help text says "Path to compiled Wasm session code"), `--output`/`-o` and `--force`/`-f` ([sign.rs#L18-L37](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/sign.rs#L18-L37), [creation_common.rs#L821-L837](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L821-L837)).
- `send-transaction` also reads its file through `--wasm-path`/`-w`, takes `--node-address`, `--id`, `-v` and `--speculative-exec`, and sends the file without the block lookup ([send.rs#L20-L45](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/send.rs#L20-L45), [lib/cli/transaction.rs#L180-L192](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L180-L192)).
- `get-transaction` takes the hash as a positional argument, plus `-a`/`--get-finalized-approvals` ([common.rs#L475-L485](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/common.rs#L475-L485), [get.rs#L31-L46](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/get.rs#L31-L46)).
- `put-transaction` and `make-transaction` always build a Version1 transaction ([lib/cli/transaction.rs#L116-L117](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L116-L117)), and `get-transaction` always wraps the hash as a Version1 transaction hash ([get.rs#L84-L90](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/get.rs#L84-L90), [lib/cli.rs#L129-L138](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli.rs#L129-L138), [parse.rs#L1015-L1022](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L1015-L1022)); a v2.2.2 node looks the hash up by that type, falling back to its legacy deploy records only for deploy hashes, so look up hashes returned by the deploy commands with `get-deploy <HASH>` ([versioned_databases.rs#L38-L47](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/block_store/lmdb/versioned_databases.rs#L38-L47), [versioned_databases.rs#L155-L179](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/block_store/lmdb/versioned_databases.rs#L155-L179), [deploy/get.rs#L52-L53](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/deploy/get.rs#L52-L53)).
- `list-transactions` returns empty hash lists for a legacy `Version1` block, where `list-deploys` returns the block's deploy hashes; for a `Version2` block, `list-transactions` lists every transaction and `list-deploys` only the deploys ([list.rs#L32-L49](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/list.rs#L32-L49), [deploy/list.rs#L32-L47](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/deploy/list.rs#L32-L47), [block.rs#L191-L204](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/block.rs#L191-L204)).
- `--force` is an argument of `make-transaction` itself, so it goes before the subcommand name: `make-transaction --force transfer ...` ([make.rs#L24-L45](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/make.rs#L24-L45)).

## Pricing and payment on Mainnet and Testnet

- `classic` builds a `PaymentLimited` pricing mode and errors without `--gas-price-tolerance`, `--payment-amount` or `--standard-payment`; `fixed` needs only `--gas-price-tolerance`; `reserved` needs `--receipt` ([parse.rs#L914-L1013](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L914-L1013)).
- The Mainnet and Testnet chainspecs set `pricing_handling = { type = 'payment_limited' }` and `allow_prepaid = false` ([mainnet chainspec#L129-L139](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L129-L139), [testnet chainspec#L135-L139](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L135-L139)).
- A v2.2.2 node rejects a `Fixed` transaction unless the chain uses fixed pricing, and a `Prepaid` transaction (what `reserved` builds) unless `allow_prepaid` is on, so use `classic` on both networks ([meta_transaction_v1.rs#L577-L593](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L577-L593), [parse.rs#L997-L1006](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L997-L1006)).
- Both chainspecs set `min_gas_price` and `max_gas_price` to 1, and a v2.2.2 node rejects a tolerance below `min_gas_price` (`GasPriceToleranceTooLow`) or above `max_gas_price` (`InvalidPricingMode`), so on both networks `--gas-price-tolerance` must be exactly 1 ([mainnet chainspec#L509-L510](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L509-L510), [testnet chainspec#L511-L512](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L511-L512), [meta_transaction_v1.rs#L100-L128](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L100-L128), [transaction_acceptor.rs#L120-L135](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/transaction_acceptor.rs#L120-L135)).
- The tolerance means "do not include this transaction in a block if the current gas price is greater than this number" ([pricing_mode.rs#L43-L52](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L43-L52)).
- Under payment-limited pricing the node rejects a zero payment and any payment below the chainspec cost of the entry point; the floors below come from the v2.2.2 Mainnet chainspec, and Testnet uses the same values ([meta_transaction_v1.rs#L497-L570](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L497-L570), [mainnet chainspec#L448-L473](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L448-L473), [testnet chainspec#L453-L475](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L453-L475), [testnet chainspec#L179](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L179)).

- Both chainspecs set `refund_handling` to return 75% of the unused payment (the payment amount minus the execution costs) to the sender and `fee_handling` to burn fees, so a payment above the real cost loses 25% of the excess ([mainnet chainspec#L108-L126](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L108-L126), [testnet chainspec#L108-L126](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L108-L126)).
- Under payment-limited pricing, a contract call or a session without `--install-upgrade` goes to the Wasm lane with the smallest gas limit whose gas, size and args limits all fit, its payment amount is its gas limit, and a transaction that fits no lane is rejected with `NoLaneMatch` ([transaction_v1.rs#L740-L782](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/transaction_v1.rs#L740-L782), [transaction.rs#L668-L681](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction.rs#L668-L681), [transaction_v1_config.rs#L414-L435](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/chainspec/transaction_config/transaction_v1_config.rs#L414-L435), [transaction_v1_config.rs#L465-L478](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/chainspec/transaction_config/transaction_v1_config.rs#L465-L478), [pricing_mode.rs#L142-L144](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L142-L144)).

- `invocable-entity-alias` and `package-name` resolve the name in the initiating account's named keys, and an unknown name fails with `NamedKeyNotFound` ([engine_state/mod.rs#L78-L105](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/engine_state/mod.rs#L78-L105), [execution_kind.rs#L64-L116](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/engine_state/execution_kind.rs#L64-L116)).
- clap requires neither `--session-entry-point` nor `--transaction-package-name`; when either is missing the client substitutes an empty string and builds the transaction with an empty custom entry point or package name, so always pass the ones the subcommand takes ([creation_common.rs#L1163-L1182](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L1163-L1182), [creation_common.rs#L1245-L1268](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L1245-L1268), [creation_common.rs#L2344-L2349](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2344-L2349), [transaction_v1_builder.rs#L318-L330](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction_v1_builder.rs#L318-L330)).
- A `session` transaction on the default VM1 runtime always uses the `call` entry point; the client applies `--session-entry-point` to a session only for `vm-casper-v2` ([transaction_v1_builder.rs#L416-L432](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction_v1_builder.rs#L416-L432), [lib/cli/transaction.rs#L100-L105](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L100-L105)).
- Pass `--install-upgrade` when the Wasm installs or upgrades a contract: in v2.2.2, session Wasm sent without that flag gets `NotAllowedToAddContractVersion` when it tries to add a contract version (legacy deploys are exempt), and install/upgrade sessions go to lane 2 ([runtime/mod.rs#L2655-L2660](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/runtime/mod.rs#L2655-L2660), [executor.rs#L95-L100](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/execution/executor.rs#L95-L100), [execution_kind.rs#L56-L59](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/engine_state/execution_kind.rs#L56-L59), [transaction_v1.rs#L765-L772](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/transaction_v1.rs#L765-L772)).
- `session`, `invocable-entity`, `invocable-entity-alias`, `package` and `package-name` also take `--transaction-runtime` (`vm-casper-v1`, the default, or `vm-casper-v2`, which requires `--transferred-value`/`-T`) and `--chunked-args` ([creation_common.rs#L2186-L2194](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2186-L2194), [creation_common.rs#L2238-L2245](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2238-L2245), [creation_common.rs#L2302-L2312](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2302-L2312), [creation_common.rs#L2363-L2372](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2363-L2372), [creation_common.rs#L2428-L2438](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2428-L2438), [creation_common.rs#L587-L628](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L587-L628), [creation_common.rs#L2679-L2700](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2679-L2700)).
- Both networks set `vm_casper_v2 = false`, so leave the runtime at `vm-casper-v1` there; the client reads `--transferred-value` only for `vm-casper-v2` ([mainnet chainspec#L205-L207](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L205-L207), [testnet chainspec#L207-L209](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L207-L209), [creation_common.rs#L2679-L2700](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2679-L2700)).
- Do not use `--chunked-args` on Mainnet or Testnet: it replaces the named runtime args with raw bytes, and a v2.2.2 node rejects a VM1 transaction whose args are not named with `ExpectedNamedArguments` ([creation_common.rs#L315-L344](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L315-L344), [parse.rs#L246-L263](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L246-L263), [meta_transaction_v1.rs#L391-L408](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L391-L408)).
- Both chainspecs set `minimum_delegation_amount` to 500,000,000,000 motes (500 CSPR); it is the floor for each validator's own minimum, because the node rejects an `add-bid` with a lower `--minimum-delegation-amount` and a new bid without one gets the chainspec value ([mainnet chainspec#L71-L72](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L71-L72), [testnet chainspec#L71-L72](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L71-L72), [arg_handling.rs#L315-L321](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/arg_handling.rs#L315-L321), [auction.rs#L113-L117](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L113-L117), [auction.rs#L163-L164](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L163-L164)).
- A first delegation to a validator must be at least that validator's minimum and at most its maximum, or the auction fails it with `DelegationAmountTooSmall` or `DelegationAmountTooLarge`; a top-up to an existing delegation has no minimum, but the total may not exceed the maximum, and the node's transaction checks skip the minimum "since this could be a second delegation" ([detail.rs#L853-L873](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction/detail.rs#L853-L873), [arg_handling.rs#L381-L400](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/arg_handling.rs#L381-L400)).
- An `undelegate` or `redelegate` that would leave less than the validator's minimum delegation unbonds the delegator's whole stake with that validator ([detail.rs#L1553-L1567](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction/detail.rs#L1553-L1567), [auction.rs#L352-L399](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L352-L399)).
- Both chainspecs set `unbonding_delay = 7`, the "number of eras that need to pass to be able to withdraw unbonded funds", and `era_duration = '120 minutes'`, with an era lasting longer if needed to reach `minimum_era_height = 100` blocks ([mainnet chainspec#L26-L30](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L26-L30), [mainnet chainspec#L54-L55](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L54-L55), [testnet chainspec#L26-L30](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L26-L30), [testnet chainspec#L54-L55](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L54-L55)).
- Both chainspecs set `minimum_bid_amount` to 500,000,000,000 motes (500 CSPR), and withdrawing a bid to below it "will be treated as a full unbond of a validator and their associated delegators" ([mainnet chainspec#L75-L77](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L75-L77), [testnet chainspec#L75-L77](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L75-L77)).
- `put-transaction withdraw-bid` reads the chainspec and auction state from the node and refuses with `ReducedStakeBelowMinAmount` when the stake left would fall below `minimum_bid_amount`; `--min-bid-override` turns that refusal, or a failed lookup, into a printed warning and sends the transaction, and `make-transaction` runs no such check ([deploy.rs#L56-L97](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/deploy.rs#L56-L97), [lib/cli/transaction.rs#L130-L168](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L130-L168), [lib/cli/transaction.rs#L645-L671](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L645-L671)).
- `put-transaction withdraw-bid-all` takes no amount: it looks up the validator's staked amount in the node's auction state, fails with `FailedToGetAuctionState` when there is no bid, and sets `--min-bid-override` itself ([put.rs#L152-L173](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/put.rs#L152-L173), [creation_common.rs#L1778-L1790](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L1778-L1790)).

## Worked examples

Set `<CHAIN-NAME>` to `casper-test` on Testnet or `casper` on Mainnet ([testnet chainspec#L20](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L20), [mainnet chainspec#L20](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L20)). The payment amounts are the chainspec costs, which are the same on both networks (see the floor table above), and at the gas price of 1 each costs that many motes ([testnet chainspec#L511-L512](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L511-L512), [pricing_mode.rs#L158-L171](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L158-L171)). Replace `<PUBLIC-KEY-HEX>` with your own public key and the other angle-bracket values with real data.

Native CSPR transfer of 2.5 CSPR, the minimum transfer amount, paying the 0.1 CSPR transfer cost ([testnet chainspec#L201-L202](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L201-L202), [testnet chainspec#L475](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L475)):

casper-client put-transaction transfer \
  --node-address http://<NODE-ADDRESS>:7777 \
  --chain-name <CHAIN-NAME> \
  --secret-key <PATH-TO-YOUR-SECRET-KEY> \
  --target <RECIPIENT-PUBLIC-KEY-HEX> \
  --transfer-amount 2500000000 \
  --pricing-mode classic \
  --payment-amount 100000000 \
  --gas-price-tolerance 1 \
  --standard-payment true
```

Delegate 500 CSPR, paying the 2.5 CSPR delegate cost. As a first delegation this succeeds only if the validator's own minimum delegation is 500 CSPR or less and its maximum 500 CSPR or more (see above) ([testnet chainspec#L455](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L455), [detail.rs#L866-L873](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction/detail.rs#L866-L873)):

Install a contract from compiled Wasm. The payment is the transaction's gas limit and must be between 2,500,000,000 and 812,500,000,000; the docs suggest estimating it on Testnet, and only 75% of any excess comes back ([testnet chainspec#L179](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L179), [testnet chainspec#L199-L200](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L199-L200), [testnet chainspec#L117](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L117), [pricing_mode.rs#L142-L144](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L142-L144), [docs.casper.network: Sending Transactions](https://docs.casper.network/developers/cli/sending-transactions), [sending-transactions.md#L1414](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/sending-transactions.md#L1414)):

  --standard-payment true
```

Call the `transfer` entry point of a contract package whose hash is stored under a named key of the sending account; the same 2,500,000,000 `baseline_motes_amount` floor applies ([execution_kind.rs#L97-L109](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/engine_state/execution_kind.rs#L97-L109), [meta_transaction_v1.rs#L568-L570](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L568-L570)):

```bash
casper-client put-transaction package-name \
  --node-address http://<NODE-ADDRESS>:7777 \
  --chain-name <CHAIN-NAME> \
  --secret-key <PATH-TO-YOUR-SECRET-KEY> \
  --transaction-package-name <PACKAGE-NAMED-KEY> \
  --session-entry-point transfer \
  --session-arg "recipient:key='account-hash-<RECIPIENT-ACCOUNT-HASH-HEX>'" \
  --session-arg "amount:u256='1000'" \
  --pricing-mode classic \
  --payment-amount <PAYMENT-AMOUNT> \
  --gas-price-tolerance 1 \
  --standard-payment true
```

Offline flow: build an unsigned transfer on a machine that does not hold the secret key, sign it where the key lives, then send it ([make.rs#L18-L22](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/make.rs#L18-L22), [lib/cli/transaction.rs#L130-L142](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L130-L142), [creation_common.rs#L705-L709](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L705-L709)):

```bash
casper-client make-transaction transfer \
  --chain-name <CHAIN-NAME> \
  --initiator-address <PUBLIC-KEY-HEX> \
  --target <RECIPIENT-PUBLIC-KEY-HEX> \
  --transfer-amount 2500000000 \
  --pricing-mode classic \
  --payment-amount 100000000 \
  --gas-price-tolerance 1 \
  --standard-payment true \
  --output transfer.json

casper-client sign-transaction \
  --wasm-path transfer.json \
  --secret-key <PATH-TO-YOUR-SECRET-KEY> \
  --output transfer-signed.json

casper-client send-transaction \
  --node-address http://<NODE-ADDRESS>:7777 \
  --wasm-path transfer-signed.json

casper-client get-transaction --node-address http://<NODE-ADDRESS>:7777 <TRANSACTION-HASH>
```

- For a multi-signature account, each signer runs `sign-transaction` on the file in turn before it is sent ([docs.casper.network: Sending Transactions](https://docs.casper.network/developers/cli/sending-transactions), [sending-transactions.md#L1406](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/sending-transactions.md#L1406)).

## Pitfalls in 5.0.1

- Passing `--transfer-id` to `put-transaction transfer` or `make-transaction transfer` panics: the arg is registered without a value parser but read back with `get_one::<u64>`, a clap type mismatch ([creation_common.rs#L2579-L2603](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2579-L2603)). Omit it, or use the legacy `transfer` or `make-transfer` command, both of which require it ([deploy/transfer.rs#L69-L87](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/deploy/transfer.rs#L69-L87), [deploy/make_transfer.rs#L19-L26](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/deploy/make_transfer.rs#L19-L26)).
- The docs describe the transfer ID as a memo that some recipients need, for example accounts whose off-chain systems track individual sub-balances, so for those recipients use the legacy command ([docs.casper.network: Direct Token Transfer](https://docs.casper.network/developers/cli/transfers/direct-token-transfer), [direct-token-transfer.md#L36](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/transfers/direct-token-transfer.md#L36)).
- The package-by-name subcommand is `package-name`, although the 5.0.0 CHANGELOG calls the alias subcommands `invocable-alias` and `package-alias` ([creation_common.rs#L2319](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2319), [CHANGELOG.md#L12-L30](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/CHANGELOG.md#L12-L30)).
- The docs' `put-txn session` example uses `--transaction-path`, `--category` and `--pricing-mode fixed` ([docs.casper.network: Sending Transactions](https://docs.casper.network/developers/cli/sending-transactions), [sending-transactions.md#L44-L52](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/sending-transactions.md#L44-L52)). The v5.0.1 `session` subcommand has no `--transaction-path` or `--category`; use `--wasm-path` and `--install-upgrade`, and use `classic` pricing on Mainnet and Testnet ([creation_common.rs#L2428-L2438](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L2428-L2438), [creation_common.rs#L742-L778](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L742-L778)).
- The client's own README still shows `Casper client 2.0.0` help output and a legacy `transfer --amount … --target-account … --payment-amount` example ([README.md#L17](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/README.md#L17), [README.md#L141-L148](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/README.md#L141-L148)).

## Mapping: 1.x commands to 5.x

Every `put-transaction`/`make-transaction` row below also needs `--chain-name`, `--gas-price-tolerance`, `--payment-amount` and `--standard-payment` (use `true`), and a `put-transaction` row needs `--secret-key` ([creation_common.rs#L742-L778](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L742-L778), [parse.rs#L923-L941](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L923-L941), [lib/cli/transaction.rs#L149-L159](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/transaction.rs#L149-L159)).

| 1.x tutorial command | 5.x command |
|---|---|
| `transfer --amount A --target-account <RECIPIENT-PUBLIC-KEY-HEX> --transfer-id N` | `put-transaction transfer --transfer-amount A --target <RECIPIENT-PUBLIC-KEY-HEX>` (no transfer ID; see pitfalls) |
| `put-deploy --session-path x.wasm` | `put-transaction session --wasm-path x.wasm` (add `--install-upgrade` for installs) |
| `put-deploy --session-hash hash-H --session-entry-point E` | `put-transaction invocable-entity --contract-hash hash-H --session-entry-point E` |
| `put-deploy --session-name N --session-entry-point E` | `put-transaction invocable-entity-alias --entity-alias N --session-entry-point E` |
| `put-deploy --session-package-hash hash-H --session-entry-point E` | `put-transaction package --contract-package-hash hash-H --session-entry-point E` |
| `put-deploy --session-package-name N --session-entry-point E` | `put-transaction package-name --transaction-package-name N --session-entry-point E` |
| `put-deploy` to the auction `delegate` / `undelegate` / `redelegate` entry points | `put-transaction delegate --delegator <PUBLIC-KEY-HEX> --validator <VALIDATOR-PUBLIC-KEY-HEX> --transaction-amount A`; `undelegate` takes the same flags, `redelegate` adds `--new-validator` |
| `put-deploy` with `add_bid.wasm` / `withdraw_bid.wasm` | `put-transaction add-bid` / `withdraw-bid` (or `withdraw-bid-all`) |
| `make-deploy …` / `make-transfer …` | `make-transaction <SUBCOMMAND> … --output FILE` |
| `sign-deploy -i IN -o OUT -k <PATH-TO-YOUR-SECRET-KEY>` | `sign-transaction -w IN -o OUT -k <PATH-TO-YOUR-SECRET-KEY>` |
| `send-deploy -i FILE` | `send-transaction -w FILE` |
| `get-deploy HASH` / `list-deploys` | `get-transaction HASH` for transactions built by `put-transaction` or `make-transaction`, and `list-transactions` for `Version2` blocks; keep `get-deploy HASH` for deploy hashes (including those from the legacy `transfer`) and `list-deploys` for legacy `Version1` blocks |
| `--session-account <PUBLIC-KEY-HEX>` | `--initiator-address <PUBLIC-KEY-HEX>` |
| `--gas-price N` | `--gas-price-tolerance N` (`--gas-price` is an alias) |
