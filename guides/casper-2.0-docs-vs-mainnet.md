# Where the Casper 2.0 docs differ from mainnet today

Verified against casper-node v2.2.2 and docs.casper.network 2.0.0 on 2026-09-11.

This page lists statements on docs.casper.network, whose newest documentation version is [2.0.0](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versions.json#L2), that are wrong or misleading for Casper mainnet as configured in [casper-node v2.2.2](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L1-L14), ordered by how likely each one is to break a transaction, a stake or an answer. Headline facts: mainnet prices transactions in [`payment_limited` mode](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L135), so the docs' `--pricing-mode fixed` is rejected; the maximum TTL is [2 hours](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L192), not 18; the minimum validator bid is [500 CSPR](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L77), not 10,000; [addressable entities are disabled](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L177); [a sustain purse takes a 2/8 share of rewards](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L184); and the docs' session flags `--transaction-path` and `--category` do not exist in casper-client 5.0.1, which uses [`--wasm-path`](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L824) and [`--install-upgrade`](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L847). Mainnet configuration values here come from `resources/mainnet/chainspec.toml` at v2.2.2 unless another file is named; at the same tag, `resources/production/chainspec.toml` still declares [protocol 2.1.2](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/production/chainspec.toml#L3) with [standard rewards](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/production/chainspec.toml#L182), and the v2.2.0 notes say of 2.1.2 that ["this version of the protocol was never applied to Mainnet"](https://github.com/casper-network/casper-node/releases/tag/v2.2.0), so it is not the mainnet file.

## 1. `--pricing-mode fixed` is rejected on mainnet

- **Docs:** [Installing Contracts](https://docs.casper.network/developers/cli/installing-contracts) says `pricing-mode` is ["Set to "fixed" for Mainnet and Testnet"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/installing-contracts.md?plain=1#L39) and ["For Mainnet and Testnet, the pricing mode is "fixed", meaning that costs are fixed per the cost table, and senders do not specify how much they pay."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/installing-contracts.md?plain=1#L48) The same `--pricing-mode fixed` appears in [Sending Transactions](https://docs.casper.network/developers/cli/sending-transactions) ([source](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/sending-transactions.md?plain=1#L51)) and [Change bid public key](https://docs.casper.network/operators/becoming-a-validator/change-bid-public-key) ([source](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/operators/becoming-a-validator/change-bid-public-key.md?plain=1#L69)). [Dynamic Gas Pricing](https://docs.casper.network/concepts/economics/dynamic-gas-pricing) says ["The current gas price and the slot’s maximum gas cost determine how much CSPR gets locked up for a transaction."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/dynamic-gas-pricing.md?plain=1#L55)
- **Mainnet:** the chainspec sets `pricing_handling = { type = 'payment_limited' }`, the mode in which ["senders of transaction self-specify how much they pay"](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L129-L135), and the v2.0.0 production chainspec already set [`payment_limited`](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L133), so the docs were wrong from 2.0.0 on. A node returns `InvalidPricingMode` for a `Fixed` transaction unless the chainspec's handling is `Fixed` ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L577-L584)). Under `PaymentLimited` the gas limit is the sender's `payment_amount` and only `Fixed` takes the lane's maximum ([pricing_mode.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L142-L148)), except that a native transfer's gas limit is the mint `transfer` cost whatever the pricing mode ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L843-L853)). The v2.2.2 testnet chainspec is also [`payment_limited`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/testnet/chainspec.toml#L135).
- **Payment floors under `payment_limited`:** a native transfer must pay at least the mint `transfer` cost, a native auction call at least the cost listed for its entry point (`activate_bid` is checked against the `add_bid` cost), and anything else at least `baseline_motes_amount` ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L502-L570)); on mainnet those are [100,000,000 motes](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L473), [2,500,000,000 motes for `delegate`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L453), [5,000,000,000 motes for `change_bid_public_key`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L463) and [2,500,000,000 motes](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L179).
- **Consequence:** a transaction built from these pages is refused as invalid, so nothing gets installed or called.

In casper-client 5.0.1, `--pricing-mode classic` builds `PaymentLimited` and requires `--payment-amount`, `--gas-price-tolerance` and `--standard-payment` ([parse.rs](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L922-L966)); `classic` is the default ([creation_common.rs](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L485-L500)). Mainnet's chain name is [`casper`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L20), a native transfer must move at least [2,500,000,000 motes](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L199-L200) ([arg_handling.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/arg_handling.rs#L188-L197)), and `--target` accepts a public key in hex ([parse.rs](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L494-L496)). A native transfer in the mainnet shape:

```bash
casper-client put-transaction transfer \
  --node-address <NODE-ADDRESS> \
  --chain-name <CHAIN-NAME> \
  --secret-key <PATH-TO-YOUR-SECRET-KEY> \
  --target <PUBLIC-KEY-HEX> \
  --transfer-amount 2500000000 \
  --pricing-mode classic \
  --payment-amount 100000000 \
  --standard-payment true \
  --gas-price-tolerance 1
```

**`--gas-price-tolerance` is not a payment cap.** [Installing Contracts](https://docs.casper.network/developers/cli/installing-contracts) calls it ["The maximum amount of gas a user is willing to pay for execution"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/installing-contracts.md?plain=1#L38), [Change bid public key](https://docs.casper.network/operators/becoming-a-validator/change-bid-public-key) calls it ["Maximum payment for the Transaction in motes."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/operators/becoming-a-validator/change-bid-public-key.md?plain=1#L80), and [Sending Transactions](https://docs.casper.network/developers/cli/sending-transactions) says ["Execution consumed 371736413663 motes, which is less than our `gas price tolerance` of 1000000000000."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/sending-transactions.md?plain=1#L1338) and that an out-of-gas error means ["you did not specify a high enough value in the `--gas-price-tolerance` arg"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/sending-transactions.md?plain=1#L1339). In casper-types it is a `u8` documented as ["minimum 1"](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L46) that means ["do not include this transaction in a block if the current gas price is greater than this number"](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L47-L48), stored next to the separate `payment_amount` ([pricing_mode.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L43-L52)). casper-client 5.0.1 parses the value as a `u8` ([parse.rs](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/parse.rs#L942-L947)), so a value like 1000000000000 fails in the client. The node rejects a tolerance below `min_gas_price` with `GasPriceToleranceTooLow` and one above `max_gas_price` with `InvalidPricingMode` ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L100-L128)), and mainnet sets [both to 1](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L509-L510), so the only tolerance mainnet accepts on a Transaction V1 is 1. Under `payment_limited` the gas limit equals `payment_amount` ([pricing_mode.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L142-L144)), except for a native transfer, whose gas limit is the mint `transfer` cost ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L843-L853)). Consequence: raising the tolerance cannot fix an out-of-gas failure; raise `--payment-amount`.

**There is no size category to pick.** Under `payment_limited`, a non-install Wasm transaction goes to the first Wasm lane, ordered by gas limit, whose gas limit, size and argument limits fit its `payment_amount` and bytes ([transaction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction.rs#L674-L681), [transaction_v1_config.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/chainspec/transaction_config/transaction_v1_config.rs#L414-L435), [ordering](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/chainspec/transaction_config/transaction_v1_config.rs#L465-L473)); `--install-upgrade` sends it to the install/upgrade lane ([transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/transaction_v1.rs#L770-L772)). Mainnet's lanes ([chainspec](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L216-L231)):

| Lane | Id | Max transaction size | Max args size | Gas limit | Per block |
|---|---|---|---|---|---|
| Native mint | 0 | 2,048 B | 1,024 B | 100,000,000 | 325 |
| Native auction | 1 | 3,096 B | 2,048 B | 2,500,000,000 | 325 |
| Install/upgrade | 2 | 750,000 B | 2,048 B | 1,000,000,000,000 | 1 |
| Wasm | 3 | 750,000 B | 2,048 B | 1,000,000,000,000 | 1 |
| Wasm | 4 | 131,072 B | 1,024 B | 100,000,000,000 | 2 |
| Wasm | 5 | 65,536 B | 512 B | 5,000,000,000 | 40 |

Consequence: a small contract call that pays more than 5,000,000,000 motes leaves lane 5 (40 per block). Up to 100,000,000,000 motes it goes to lane 4 (2 per block), and above that to lane 3 (1 per block), whose 1,000,000,000,000 limit is out of reach: the node rejects any transaction that declares more than the 812,500,000,000 `block_gas_limit` ([block_gas_limit](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L198), [V1](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L622-L637), [deploy](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/deploy.rs#L471-L487)) ([chainspec](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L227-L231), [transaction_v1_config.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/chainspec/transaction_config/transaction_v1_config.rs#L414-L435), [ordering](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/chainspec/transaction_config/transaction_v1_config.rs#L465-L473)).

**Only VM v1 runs on mainnet.** The JSON-RPC [Types](https://docs.casper.network/developers/json-rpc/types_chain) page lists ["`VmCasperV2` The Casper Version 2 Virtual Machine."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/json-rpc/types_chain.md?plain=1#L1555) as a transaction runtime, but mainnet sets [`vm_casper_v2 = false`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L205-L207), and the node rejects a transaction whose runtime is `VmCasperV2` with `InvalidTransactionRuntime` ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L63-L77)). casper-client's `--transaction-runtime` defaults to [`vm-casper-v1`](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L592-L603) ([value](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L626)). Consequence: leave `--transaction-runtime` at its default on mainnet.

## 3. The maximum TTL is 2 hours, not 18

- **Docs:** [Sending Transactions](https://docs.casper.network/developers/cli/sending-transactions) says ["The acceptable maximum `ttl` is configurable by chain, with the Casper Mainnet maximum set to `18hours`."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/sending-transactions.md?plain=1#L1366)
- **Mainnet:** [`max_ttl = '2 hours'`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L191-L192). The v2.0.0 production chainspec already had [`'2 hours'`](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L185), and so did v1.5.8's ([`max_ttl = '2 hours'`](https://github.com/casper-network/casper-node/blob/v1.5.8/resources/production/chainspec.toml#L130)). Transactions and deploys with a longer TTL fail with `ExcessiveTimeToLive` ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L792-L802), [deploy_header.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/deploy/deploy_header.rs#L143-L153)). casper-client's default TTL is [`30min`](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L170-L172), and its help text says ["A transaction can only be included in a block"](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L173-L175) between its timestamp and timestamp plus TTL.
- **Consequence:** a transaction with a TTL above 2 hours is refused, so it must be included within 2 hours of its timestamp.

## 4. Contract calls and installs that pay under 2.5 CSPR are refused

- **Docs:** [Calling Contracts](https://docs.casper.network/developers/cli/calling-contracts) pays ["`--payment-amount 100000000`"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/calling-contracts.md?plain=1#L55), as does the [Quickstart](https://docs.casper.network/resources/quick-start) ([source](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/resources/quick-start.md?plain=1#L155)); the [Fungible Token Workflow](https://docs.casper.network/resources/tokens/cep18/full-tutorial) installs `cep18.wasm` with ["`--payment-amount 1000000`"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/resources/tokens/cep18/full-tutorial.md?plain=1#L242). The Calling Contracts and Fungible Token Workflow examples target `casper-test` ([L53](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/calling-contracts.md?plain=1#L53), [L240](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/resources/tokens/cep18/full-tutorial.md?plain=1#L240)).

- **Consequence:** on mainnet, expect `account-hash-…` and `hash-…` keys and `Account`/`Contract` JSON; code or answers that look for `entity-account-`, `entity-contract-` or an `AddressableEntity` object will not match.

## 6. The minimum validator bid is 500 CSPR

- **Docs:** [Bonding](https://docs.casper.network/operators/becoming-a-validator/bonding) says ["This value is currently 10,000 CSPR as seen as the extract from `chainspec.toml` below."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/operators/becoming-a-validator/bonding.md?plain=1#L13) and shows [`minimum_bid_amount = 10_000_000_000_000`](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/operators/becoming-a-validator/bonding.md?plain=1#L18). [Unbonding](https://docs.casper.network/operators/becoming-a-validator/unbonding) builds its guardrail table on ["<10,000,000,000,000 motes"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/operators/becoming-a-validator/unbonding.md?plain=1#L62).
- **Mainnet:** [`minimum_bid_amount = 500_000_000_000`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L75-L77), which is 500 CSPR; the v2.2.0 notes say ["the `minimum_bid_amount` threshold has been reduced to 500 CSPR as part of the protocol upgrade"](https://github.com/casper-network/casper-node/releases/tag/v2.2.0). The docs' figure is v2.0.0's [`10_000_000_000_000`](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L77).
- **Withdrawal rules:** withdrawing more than the staked amount returns `UnbondTooLarge` ([auction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L240-L247)); a withdrawal that leaves less than `minimum_bid_amount` unbonds the validator and all its delegators ([auction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L255-L285)). casper-client's `--min-bid-override` guardrail reads `minimum_bid_amount` from the node's chainspec ([deploy.rs](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/deploy.rs#L63-L73), [check](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/lib/cli/deploy.rs#L84-L91)).
- **Consequence:** on mainnet both the full-unbond threshold and the client guardrail sit at 500 CSPR, not at the documented 10,000 CSPR.

## 7. Delegation: costs, forced unbonding and the new rate floor

- **Undelegation cost.** [Undelegate Tokens](https://docs.casper.network/users/undelegate-ui) says ["Note that undelegation costs approximately 0.5 CSPR."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/users/csprlive/undelegate-ui.md?plain=1#L10), while [Undelegating Tokens](https://docs.casper.network/developers/cli/undelegate) says ["Calling the `undelegate` entry point on the auction contract has a fixed cost of 2.5 CSPR."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/undelegate.md?plain=1#L58) The second matches mainnet: `undelegate` costs [2,500,000,000 motes](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L454), and a native undelegate must pay at least that ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L534-L536), [check](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L565-L567)). Consequence: keep at least 2.5 CSPR liquid to undelegate.
- **A partial undelegation can unbond everything.** The same line of [Undelegating Tokens](https://docs.casper.network/developers/cli/undelegate) says ["There is no minimum amount required for the undelegation call."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/developers/cli/undelegate.md?plain=1#L58) If the stake left is below the validator's minimum delegation amount, the whole delegation is unbonded ([detail.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction/detail.rs#L1556-L1566)), as [Delegating Tokens](https://docs.casper.network/users/delegating) does note ([source](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/users/delegating.md?plain=1#L109)). Consequence: check the validator's minimum before undelegating part of a stake.
- **Top-ups count toward the validator's maximum.** [Bonding](https://docs.casper.network/operators/becoming-a-validator/bonding) describes `maximum_delegation_amount` as ["Maximum allowed delegation amount in motes"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/operators/becoming-a-validator/bonding.md?plain=1#L57). A `delegate` call from an existing delegator fails with `DelegationAmountTooLarge` when its current stake plus the new amount exceeds the validator's maximum ([detail.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction/detail.rs#L856-L863)). The v2.2.0 notes say ["the system considers the sum of any previously staked tokens and the current amount"](https://github.com/casper-network/casper-node/releases/tag/v2.2.0) and that, when the fix is applied, ["any delegations that exceed the maximum will be partially unbonded to reduce their delegated amount to the maximum limit"](https://github.com/casper-network/casper-node/releases/tag/v2.2.0). Consequence: compare the validator's maximum with your total stake, not with the new amount.
- **Rewards can trigger undelegation.** At distribution, a delegator whose stake plus reward is below the validator's minimum is queued for full undelegation, and the part above the validator's maximum is queued for undelegation ([auction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L869-L892)); the queued undelegations run in the same call ([auction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L958-L961)). Consequence: a delegation held at a validator's maximum sends each new reward back through unbonding.
- **Minimum delegation rate.** v2.2.0 added ["a new chainspec setting `minimum_delegation_rate`"](https://github.com/casper-network/casper-node/releases/tag/v2.2.0), and mainnet sets [`minimum_delegation_rate = 0`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L88-L89). The notes say it ["will be set to 0 with this release, which keeps behavior inert"](https://github.com/casper-network/casper-node/releases/tag/v2.2.0) and that once a minimum exists ["any attempt to modify the validator's pre-existing stake either through `add_bid` or `withdraw_bid` will require the validator to set a delegation rate to at least the minimum"](https://github.com/casper-network/casper-node/releases/tag/v2.2.0), adding ["The same applies when a validator attempts to modify their reservations."](https://github.com/casper-network/casper-node/releases/tag/v2.2.0) Consequence: a 0% validator rate is still valid today, but a later non-zero floor would apply at the validator's next `add_bid`, `withdraw_bid` or reservation change.

## 8. The gas price is pinned at 1, fees are burned, and successful Wasm transactions get 75% of unused payment back

- **Docs:** [Dynamic Gas Pricing](https://docs.casper.network/concepts/economics/dynamic-gas-pricing) says ["With Casper 2.0, the multiple is configured to adjust between 1 and 3."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/dynamic-gas-pricing.md?plain=1#L21) and shows [`max_gas_price = 3`](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/dynamic-gas-pricing.md?plain=1#L49). [Gas Cost](https://docs.casper.network/concepts/economics/gas-concepts) says ["Currently, gas is priced at a fixed price of 1 mote (1 CSPR is 10^9 motes) per 1 unit of gas."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/gas-concepts.md?plain=1#L17) but, in the same paragraph, that the multiplier ["is dynamic and based on current network usage"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/gas-concepts.md?plain=1#L17). The [economics overview](https://docs.casper.network/economics) says ["a future release (after Casper 2.0 mainnet activation) will enable fee elimination model by default, setting the `no_fee`,`no_refund`, and `fixed` pricing configurations"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/index.md?plain=1#L48) and that the fee elimination model ["has replaced the refund behavior"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/index.md?plain=1#L58), and [Build on Casper](https://docs.casper.network/resources/build-on-casper/introduction) links to ["eliminating transaction fees"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/resources/build-on-casper.md?plain=1#L80) on Mainnet.
- **Mainnet gas price:** [`max_gas_price = 1` and `min_gas_price = 1`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L509-L510), and the price only rises ["if lower than max_gas_price"](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L504); v2.0.0 also had [`max_gas_price = 1`](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L502). With [`min_gas_price` equal to `max_gas_price`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L509-L510), Gas Cost's 1-mote price holds on mainnet and its "dynamic" multiplier cannot move.
- **Mainnet fees and refunds:** [`fee_handling = { type = 'burn' }`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L118-L126), under which the node burns the fee ([operations.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L1014-L1023)); v2.1.0 introduced this ["burn mechanism for fees on transaction"](https://github.com/casper-network/casper-node/releases/tag/v2.1.0), replacing v2.0.0's [`pay_to_proposer`](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L124). Refunds are [`refund` with ratio 75/100](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L117), under which ["a ratio of the unspent token is returned to the spender"](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L111): the node refunds 75% of the unused gas limit at the current gas price and charges the rest of the cost, gas limit times gas price, as the fee ([internal.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/handle_payment/internal.rs#L100-L116), [operations.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L264-L269), [refund at the current gas price](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L903-L948)). That refund applies only when execution succeeds: when it fails, the node counts the full cost as consumed ([operations.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L866-L872)), so there is no unused gas left to refund ([internal.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/handle_payment/internal.rs#L100-L104)).
- **Consequence:** a Transaction V1's [`--gas-price-tolerance`](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/transaction/creation_common.rs#L424-L444) must be exactly 1, because the node rejects a V1 tolerance below `min_gas_price` or above `max_gas_price` ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L100-L128)); a deploy's gas price only has to be at least `min_gas_price` and fit in a `u8` ([deploy.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/deploy.rs#L446-L453), [conversion](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/deploy.rs#L1538-L1540)), but a deploy is charged at the current gas price, not its own ([operations.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L264-L269)), and that price never rises above 1 ([chainspec](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L504-L510)).
- **Consequence for `--payment-amount`:** fees are burned ([chainspec](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L126), [operations.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L1014-L1023)). A Wasm transaction that succeeds gets back 75% of its unused payment and loses the other 25% ([chainspec](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L117), [operations.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L237-L241), [internal.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/handle_payment/internal.rs#L100-L116)). Sent with custom payment (`--standard-payment false`), a native transaction is not executed and is charged at least the 2,500,000,000-mote `baseline_motes_amount` penalty, because a node builds a Transaction V1's custom payment only from session Wasm, so a native target's payment fails before anything runs ([meta_transaction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction.rs#L117-L135), [wasm_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/engine_state/wasm_v1.rs#L1028-L1048), [zero-gas failure](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/engine_state/wasm_v1.rs#L595-L607), [penalty](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L444-L538), [no execution](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L593-L604), [chainspec](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L178-L179)). Sent with standard payment, a native transaction gets no refund, because the node counts its whole gas limit as consumed ([operations.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L647-L715), [types.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/types.rs#L188-L191), [internal.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/handle_payment/internal.rs#L100-L104)); at mainnet's gas price of 1 a native auction call such as `delegate` is therefore charged its full `--payment-amount` ([pricing_mode.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/pricing_mode.rs#L142-L171), [operations.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L977-L986), [chainspec](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L509-L510)), and a native transfer is charged the mint `transfer` cost, [100,000,000 motes](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L473), whatever payment amount it declares ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L843-L853), [transaction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction.rs#L431-L439)). A transaction whose execution fails gets no refund at all ([operations.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/operations.rs#L866-L872), [internal.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/handle_payment/internal.rs#L100-L104)). So pay a native auction call exactly its payment floor from section 1 ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L522-L567)), and set a Wasm transaction's `--payment-amount` close to its expected cost but not below the 2,500,000,000-mote floor from section 4 ([meta_transaction_v1.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/types/transaction/meta_transaction/meta_transaction_v1.rs#L568-L570), [deploy.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/transaction/deploy.rs#L570-L572), [chainspec](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L178-L179)).

## 10. Rewards: a sustain purse takes 2/8, and the sample values are old

- **Docs:** [Rewards Design](https://docs.casper.network/concepts/design/rewards) says ["Each Casper network chainspec contains 4 settings related to calculating rewards:"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/design/rewards.md?plain=1#L42) and [Delegating Tokens](https://docs.casper.network/users/delegating) says ["The base reward rate is 8% of the total token supply, but since not everyone stakes, those who do earn a higher percentage."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/users/delegating.md?plain=1#L138)
- **Mainnet:** [`rewards_handling = { type = 'sustain', ratio = [2,8], … }`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L182-L184); the v2.2.1 mainnet chainspec already had it ([L184](https://github.com/casper-network/casper-node/blob/v2.2.1/resources/mainnet/chainspec.toml#L184)), with activation at era [22426](https://github.com/casper-network/casper-node/blob/v2.2.1/resources/mainnet/chainspec.toml#L14). At each distribution the auction mints `ratio` times the total of the validators' rewards into the sustain purse ([auction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L682-L711)) and scales each validator's reward, before the delegators' split, by `1 − ratio` ([detail.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction/detail.rs#L1658-L1659)). The v2.2.0 notes say ["the tokens in a sustain purse is liquid and can be transferred out"](https://github.com/casper-network/casper-node/releases/tag/v2.2.0). The 8% is the chainspec's ["Annual issuance: 8%"](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L56-L66), computed at an 8,000 ms minimum block time.
- **Consequence:** a quarter of each distribution goes to the sustain purse and validators with their delegators share the other 75%, so 8% of supply is not the stakers' base rate.
- **Staking yield (read from mainnet on 2026-09-23):** [Delegating Tokens](https://docs.casper.network/users/delegating) says ["Right now, the average yearly return is around 15%."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/users/delegating.md?plain=1#L138) That is not today's figure. Each era mints the per-round rate times the total supply for every block proposed: 5% to the proposer, and the other 95% only for finality signatures that later blocks cite ([rewards.rs L281](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/rewards.rs#L281), [L512-L586](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime/rewards.rs#L512-L586), [core_config.rs L214-L227](https://github.com/casper-network/casper-node/blob/v2.2.2/types/src/chainspec/core_config.rs#L214-L227), [chainspec L56-L66](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L56-L66), [L91-L93](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L91-L93)); the sustain purse then takes 2/8 ([L184](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L184)). In the 84 eras from 23868 to 23951 (switch blocks 8,952,933 to 9,028,289, 2026-09-16 16:21 to 2026-09-23 16:27 UTC), what validators and their delegators were paid came to 9.9% of their stake a year before compounding, or 10.4% with each era's reward added to the stake; a delegator receives that less its validator's commission. The chainspec's figures alone (8% annual issuance, 6/8 of it to stakers, a stake of 11.11 billion of a 19.97 billion CSPR supply in era 23951) give about 10.8%. Less was paid because issuance follows the blocks produced and the signatures cited, and these eras had 869 to 899 blocks where 120 minutes hold 900 at the 8-second minimum (`chain_get_block` for each switch block and `query_global_state` for the mint's `total_supply` at `https://node.mainnet.casper.network/rpc`, read 2026-09-23). The rate falls as more CSPR is staked and rises as less is, so quote it with its date or read it from the chain.
- **Sample values:** [Rewards Design](https://docs.casper.network/concepts/design/rewards) shows [`finality_signature_proportion = [1, 2]`](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/design/rewards.md?plain=1#L56), [`signature_rewards_max_delay = 3`](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/design/rewards.md?plain=1#L58) and [`round_seigniorage_rate = [7, 175070816]`](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/design/rewards.md?plain=1#L70); mainnet has [`[95, 100]`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L93), [`6`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L95) and [`[11, 563427926]`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L66). The docs' last two values are v2.0.0's ([`3`](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L93), [`[7, 175070816]`](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L66)); the block-time sample is in section 11.
- **Rewards are added to the stake:** [Delegate Tokens](https://docs.casper.network/users/delegate-ui) says both ["Staking rewards are delivered to your account's main purse after each era"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/users/csprlive/delegate-ui.md?plain=1#L85) and, in the same paragraph, ["The rewards are automatically added to your current stake on the corresponding validator."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/users/csprlive/delegate-ui.md?plain=1#L85) The code does the second: distribution adds a delegator's reward to its delegation stake ([auction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L869-L872)) and mints it into the delegation's bonding purse ([auction.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/storage/src/system/auction.rs#L953-L955)). Consequence: rewards show up in the stake, not in the main purse's liquid balance.
- **One-time issuance:** the v2.2.0 notes say ["when v2.2.0 gets activated on Mainnet, a one-time-issuance will be applied whereby new token equivalent to maximally 33% of the supply at the time of the upgrade will be minted to a designated purse"](https://github.com/casper-network/casper-node/releases/tag/v2.2.0). The mainnet [`global_state.toml`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/global_state.toml#L1-L11) that defines it ships in the v2.2.2 tag, beside a chainspec that activates [protocol 2.2.2](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L3) at [era 22931](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L14), and its comment reads ["This represents 33% of the supply at block 6972606"](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/global_state.toml#L7). Consequence: take total supply from the chain, not from the [Staking](https://docs.casper.network/concepts/economics/staking) page's ["ten billion CSPR at genesis"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/staking.md?plain=1#L23) and ["target annual supply growth rate is 8%"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/staking.md?plain=1#L23).

## 11. The minimum block time is 8 seconds, not 16

- **Docs:** [Consensus in a Casper Network](https://docs.casper.network/concepts/design/consensus) says ["On Mainnet, a new instance of consensus runs every two hours or approximately 440 blocks, depending on current network metrics."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/design/consensus.md?plain=1#L46) [Rewards Design](https://docs.casper.network/concepts/design/rewards) shows ["Minimum block time: 2^14 milliseconds"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/design/rewards.md?plain=1#L63) in its sample. The economics [Consensus](https://docs.casper.network/concepts/economics/consensus) page derives the round issuance rate from [`2^minimum_round_exponent`](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/consensus.md?plain=1#L59) and says ["an exponent of 14 corresponds to a round length of roughly 16 seconds"](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/economics/consensus.md?plain=1#L62).
- **Mainnet:** [`era_duration = '120 minutes'`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L27), [`minimum_era_height = 100`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L30) and [`minimum_block_time = '8000 ms'`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L32), so a 7,200-second era holds at most about 900 blocks; 440 matches v2.0.0's [`'16384 ms'`](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L32). The mainnet chainspec computes the seigniorage rate from [`8000` ms](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L62-L65). The v2.1.1 notes say the configuration ["speeds chain up to 8 seconds blocks and modifies settings to double windows and half capacity of blocks"](https://github.com/casper-network/casper-node/releases/tag/v2.1.1).
- **Consequence:** figures derived from 16-second blocks, such as blocks per era or reward per block, do not apply to mainnet.

## 12. A call stack holds at most 11 contracts, not 10

- **Docs:** [Call Stacks](https://docs.casper.network/concepts/callstack) says ["For the Casper Mainnet, this limit is set at `10` contracts. This does not include the initiating session code, which would still count as the *zeroth* instance within the stack."](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/callstack.md?plain=1#L29)
- **Mainnet:** [`max_runtime_call_stack_height = 12`](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/mainnet/chainspec.toml#L69-L70) is passed to the execution engine ([contract_runtime.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/node/src/components/contract_runtime.rs#L137)) as the maximum height of each execution's runtime stack ([engine_state/mod.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/engine_state/mod.rs#L124-L127), [L191-L194](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/engine_state/mod.rs#L191-L194)). That stack starts with one frame for the initiating account ([stack.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/runtime/stack.rs#L92-L98)), a push fails once it holds 12 frames ([stack.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/runtime/stack.rs#L76-L84)), and each contract call, system contracts included, pushes one frame ([runtime/mod.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/runtime/mod.rs#L2027-L2082)). The v2.0.0 and v1.5.8 production chainspecs also had [12](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L70) ([v1.5.8](https://github.com/casper-network/casper-node/blob/v1.5.8/resources/production/chainspec.toml#L70)).
- **Consequence:** not counting the initiator's frame, a mainnet call stack holds at most 11 contracts ([stack.rs](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/runtime/stack.rs#L76-L98)), one more than the [documented 10](https://github.com/casper-network/docs-redux/blob/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0/concepts/callstack.md?plain=1#L29), and system contracts count toward that limit: a contract that creates a purse or moves CSPR calls the Mint ([Mint calls](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/runtime/mod.rs#L3516-L3559), [call_contract](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/runtime/mod.rs#L1478-L1488)), which takes one of those 11 frames ([push](https://github.com/casper-network/casper-node/blob/v2.2.2/execution_engine/src/runtime/mod.rs#L2027-L2062)). Answers giving 10 or 12 as the limit are each off by one.

## How to check a doc statement yourself

1. Find the release to check against; this page used [casper-node v2.2.2](https://github.com/casper-network/casper-node/releases/tag/v2.2.2).
2. Read the network's own chainspec at that tag. Since v2.1.0, ["Configurations for networks have been moved inside resources directory."](https://github.com/casper-network/casper-node/releases/tag/v2.1.0) Use `resources/mainnet/chainspec.toml`; at v2.2.2, `resources/production/chainspec.toml` is [protocol 2.1.2](https://github.com/casper-network/casper-node/blob/v2.2.2/resources/production/chainspec.toml#L3), which the [v2.2.0 notes](https://github.com/casper-network/casper-node/releases/tag/v2.2.0) say was never applied to Mainnet. For values from before that move, v2.0.0 kept them in [`resources/production/chainspec.toml`](https://github.com/casper-network/casper-node/blob/v2.0.0/resources/production/chainspec.toml#L1-L3). Prefer tags to branch links such as the Runtime page's (section 13).
3. Ask a live node: `casper-client get-chainspec` prints the node's full TOML when run with ["'-vv'"](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/get_chainspec.rs#L21-L23) ([main.rs](https://github.com/casper-ecosystem/casper-client-rs/blob/v5.0.1/src/main.rs#L244-L247)).
4. Read the docs page's source in docs-redux at `c78e3c2`, under [`versioned_docs/version-2.0.0/`](https://github.com/casper-network/docs-redux/tree/c78e3c2040d30fd8c42cb95bc8a3b308db9d1a56/versioned_docs/version-2.0.0).
